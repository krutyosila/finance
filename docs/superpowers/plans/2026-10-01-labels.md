# User Labels and AI Selection Implementation Plan

**Goal:** Let the user manage labels, have AI select one existing label per transaction, review local corrections and scan existing transactions for relabeling, then publish it.

**Architecture:** Additive SQLite label catalog and nullable transaction reference preserve the current ledger and categories. A bounded active catalog enters the existing AI reference snapshot; exact live validation guards selection at preview and confirmation. Settings owns management, transaction forms own assignment, and AI review owns a local override.

**Tech Stack:** React 19, TypeScript, SQLite/Drizzle, existing strict AI schemas, Vitest and synthetic browser QA.

## Contracts

- `Label`: id, name, description:string|null, archived:boolean, createdAt, updatedAt.
- `LabelInput`: name:string, description?:string|null; name 1–80 and description at most 500 characters.
- `TransactionInput.labelId?:string|null`; omission preserves on update, null clears.
- `FinancialContext.labels?:Label[]` includes archived definitions to display historical assignments.
- `FinanceService.listLabels(includeArchived=false)`; createLabel, updateLabel, archiveLabel; GET/POST/PATCH/DELETE `/api/labels` with existing authorization. GET returns all for management/history; DELETE archives.
- AI reference labels contain only id/name/description, at most 200 active definitions; label references are not creatable AI record kinds.
- Server-derived `AiPlan.labelIssues?: {key:string,message:string}[]` blocks confirmation independently of financial `certain`/`issues`; a local override removes only the matching label issue.
- `LabelScanTransaction`: transactionId, transactionUpdatedAt, previousLabelId:string|null; `LabelScanSuggestion` also includes labelId:string|null. POST `/api/ai/labels/scan` accepts at most 50 transaction snapshots and returns suggestions; POST `/api/ai/labels/apply` applies at most 5,000 snapshots atomically, returning `{updated:number}`. All current row versions and active labels are revalidated. A dedicated 2mb body limit applies only to bulk application.
- The scan provider sees only aliased rows with description/category/counterparty/notes and active label definitions. No finance amounts, account references, balances or persistent IDs. Progress, cancellation, preview and explicit apply are required; failure or cancellation never writes partial changes.
- No category rewrite/seeding, no schedule labels, no ledger effects, no paid external test calls.
